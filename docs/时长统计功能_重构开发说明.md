# 多业务时长管理开发说明

更新日期：2026-10-26。本文记录已实现规则，取代原说明中美育时段数量及普通管理员范围的矛盾描述。

当前版本2.3.0新增业务生命周期、小组权限和名单导入，详见 [业务目录与小组管理](业务目录与小组管理_2.3.md)。新增6张表，不改变服务记录计时链路。

## 1. 架构与记账口径

保留 FastAPI、MySQL 5.7、原生 JavaScript 以及现有 Service 分层。业务写入继续使用数据库事务与命名写锁。

唯一时长账本仍为 `student → schedule → attendance → service_record`。只汇总 `record_status=VALID` 的整数分钟，最后除以 60 展示小时。业务归属、排班、待审核申报均不直接产生时长。每条排班最多一条考勤，每条考勤最多一条服务记录。

增量迁移后共 42 张表（含征集附件、范围授权、申报附件、审批历史与收件箱）。新增业务目录、非固定业务归属区间、每周开工设置、预约归属调整、停工快照、征集及事项与参与名单与申报、专项导入批次与来源行、请假图片、迁移标记。固定归属继续使用 slot_member，学期历史继续使用 semester_member，未另建时长账本。

service_slot 增加业务和类型，星期时段唯一键为 `(business_id, weekday, period_no)`。排班增加本次认定分钟、来源标识和花园本周确认标志。FIXED 为固定时段，WEEKLY 为每周岗位，EVENT 为非固定事项，LEGACY 为保留的旧式班次。无固定时间的类型允许起止时间为空。

## 2. 业务与负责人

| 业务 | 安排 | 认定分钟 | 普通管理员范围 |
|---|---|---|---|
| 咨询服务 | 每天5段，共35段；原时间不变 | 第3段180，其余120 | 每时段配置 |
| 美育 | 每天4段，共28段 | 120、120、180、120 | 每时段配置 |
| 青广宣传 | 每天3段，共21段 | 180、150、120 | 整项业务 |
| 开心花园 | A/B岗，无固定服务日 | 每人每周最多一次90 | 整项业务 |

美育：08:30–09:55、10:15–11:30、14:00–16:25、16:45–18:00。

青广宣传：11:30–13:30、16:35–18:35、18:35–19:35。认定分钟不按起止时间相减。

预置非固定业务：明远学术汇、讲解队、钢琴队、古筝队、科研探索、干部。专项导入和临时服务录入允许超管填写新业务名称，同名非固定业务复用；不能以固定业务名称绕过考勤导入时长。

普通管理员仍由超级管理员设置。一位管理员可以负责多个范围；青广、花园的负责人统一同步至该业务岗位，避免在不同入口产生不一致权限。美育和咨询按每个时段配置负责人。人数上限单独设置，空缺不阻止已有成员自动计时，但会阻止需要容量校验的新增排班与换入。

## 3. 周次、日历与结算

第1周从开工日所在周一开始，开工日前不排班；最后一周周日为学期结束日。每日固定业务继续服从 semester_day，调休按实际日期套用指定星期的班表。内置节假日仅包含2026年，未确认年份及待确认调休不会擅自排班。

已结束周未登记异常的固定排班默认正常，获批请假记LEAVE；当前周不预估时长。启动时及运行中每60秒同步补齐并结算，重复运行不重复记账。同步及默认结算只处理其负责类型，非固定事项不受自动结算或固定名单同步取消影响。

开心花园、青广宣传默认每周开工，业务管理员可更正当前、未来周安排。历史周仅超管附原因更正。停工撤销本周对应有效时长，并按信用流水中实际扣分冲正考勤处罚。恢复上工保留原已认定结果和手动分钟修正；原处罚按原规则恢复，重复提交不重复扣分。独立退队、停用、手动取消不会因业务恢复而自动撤销。

开心花园使用当周周日作为统计归属日，不表示实际服务日，其周安排由业务管理员决定。原有成员默认出勤；本周新加入或A/B调整需管理员确认本周已完成服务，否则不自动补计该周。后续周自动结算。岗位调整或重复确认不会让同一人同周重复计时。花园没有迟到认定。

## 4. 归属、考勤、信用与申请

- 咨询和美育不得同时归属；跨业务由超管设置完整归属及生效日。未来调整到期执行，停机后按原生效日补办，历史已认定记录保留。
- 业务内换时段仍为长期调整：原负责人初审，超管终审。跨业务不能通过普通换时段申请绕过互斥检查。
- 单项非固定业务的加入、退出由超管在业务管理调整；队员“退队”仍表示退出整个志愿队，须超管审批。
- 四项固定业务缺勤扣3；有明确时间的业务迟到扣1，不减正常认定时长。获批请假不计时、不扣分。首次升级发布迟到扣1的新规则版本，历史扣分与余额不重算；后续超管自定义规则不被重复迁移覆盖。
- 考勤改判必须原因及expected_revision，撤销旧违规，冲正实际扣分，再认定新结果。同结果重试幂等，过期版本拒绝。专项/申报记录不能通过考勤接口产生处罚。
- 超管仍可单独修正有效或作废服务记录的分钟，范围0–1440，不改变考勤、有效状态或信用。再改判考勤会恢复班次标准分钟，覆盖此前手动分钟调整，界面有提示。
- 新请假申请须文字原因和1至3张有效PNG/JPEG证明，每张不超过2MB。图片保存在数据库，不使用公开静态地址；仅本人、所属管理员及超管可读取。普通管理员打回须说明原因。历史无图申请可继续查看和处理。

## 5. 非固定事项与征集

超管或已授权的征集管理员发布征集时确定业务、服务日期范围、申报截止日期、参与名单、工作事项及每天该事项的最少/最多分钟。可按业务成员预选，并手动调整名单；发布时冻结参与名单。

队员按实际日期和事项申报，日期不能在未来；同一人、同一天、同一事项只有一个申报。上下限按每天校验，不限制整次征集合计。待审核或打回不计时，也不扣信用。打回须原因，携带新版本可修改重报；管理员初审通过仍不计时，超管终审通过在同一事务建立排班、考勤和服务记录，重复审核不重复入账。未配置征集管理员的业务由超管直接审批。

临时服务可提前建立未来排班，之后由超管确认本次分钟；当天或历史服务可直接录入认定。每次分钟独立保存，不更改其他班次标准。未来临时排班即使日期已过，也不会被按周自动当作出勤结算。

## 6. Excel导入与导出

基础资料的名单导入可选择咨询、美育、青广业务，默认咨询。校验所选业务实际存在的时段及咨询/美育互斥，仍只导入身份和归属，不导入历史时长。

专项导入由超管手填业务名称。模板位于 `core/templates/专项时长导入模板.xlsx`，另有虚构示例文件。第一张sheet第一行为表头：

`学号、姓名、学院、服务日期、工作事项、认定时长（小时）、备注`

学院、备注可选，其余必填。学号必须是文本；认定小时须能准确换算为0–1440整数分钟。禁止公式、未来日期、同表重复、同学号不同姓名、覆盖已停用/退队账号。上传限制8MB、解压内容40MB、最多10000行。已有人员密码和身份资料不覆盖，新账号须设置初始密码。

预览不写数据库。正式提交重新校验，整体事务写入队员、归属及原有记账链，保留批次与原表行号。相同业务同文件重复提交不重复入账。跨批次同学号、日期、事项的疑似重复行，必须逐行选择跳过或确认为另一项独立服务。

服务时长默认汇总全部业务，并展示分业务合计，支持业务筛选。超管仍先按姓名/学号搜索选人，后台按精确学号校验；普通管理员不可查询任意人员时长。

学期导出保留“志愿时长统计”“分队时长统计”“退队统计”三张表。业务填写真实名称；按业务和分队/岗位汇总，非固定事项单列。每周表头含周一至周日完整日期。实际日期归周，花园按统计周日归周；调休不按套用星期归周。开工日前排除，退队历史参与总计，未来周留空，当前周仅含已认定记录。业务筛选可单独选择，不受个人查询框影响。

## 7. 新接口与验证

业务目录及负责人：`GET /businesses`、`PUT /businesses/{id}/manager`。

每周安排：`GET /business-weeks`、`PUT /businesses/{id}/semesters/{id}/weeks/{week}`；花园确认：`POST /schedules/{id}/confirm-weekly`。

征集：`GET/POST /hour-collections`、`POST /hour-submissions`、`POST /hour-submissions/{id}/decision`。

专项：`POST /specialty-imports`、`GET /specialty-imports/template`。非固定名单：`PUT /businesses/{id}/members/{student_id}`。

临时服务：`POST /business-events`、`POST /schedules/{id}/recognize-event`。请假证明：`GET /applications/leave/{id}/evidence`及其图片子路径。

时长和导出增加可选business_id，归属设置增加effective_date、reason，旧调用默认咨询业务兼容。

测试全部使用隔离的volunteer_core_test。完整回归145项通过，后续关联回归83项通过，最终花园本周考勤改判及业务、前端回归40项通过；新增重点包括业务目录幂等、停工恢复信用、花园去重、跨期归属生效、申报审批重试、Excel重复处理、图片权限、API角色和导出对账。桌面1440px和窄屏390px共10个页面浏览器检查通过。

正式升级前已备份，在正式数据副本验证迁移及重复迁移，原账号、归属、排班、考勤、时长、违规、信用流水和审计记录指纹一致。迁移后不自动分配真实负责人或导入示例人员。已有学期在启动服务后继续按正常规则自动补算。

## 10. 三层征集审批与通知（2.2.0）


- **授权入口：**超管进入“征集管理范围 → 设置管理员范围”，选择已有普通管理员和一个或多个非固定业务，保存后立即生效。普通管理员也可以在同页“申请管理范围”，经超管批准后生效。固定排班的咨询、美育、花园、青广考勤管理权限继续使用原有设置。撤销征集授权后，管理员不能再读该业务征集、附件或执行审批。
- **发布和范围：**授权管理员可向所管业务当前有效归属的在队队员发布征集，跨选也仅限其已授权业务；超管可跨全队。名单发布时冻结。事项改为三个固定输入框，最低/最高时长单位均为整数分钟，按每人每天每事项限制，可添加多项。
- **志愿者申报附件：**保留文字说明，增加最多3个文件、每个2MB。支持PDF、DOCX、XLSX、TXT、JPG、PNG，后端验证实际格式。仅申报本人、当前授权的该业务征集管理员和超管可读取。被打回后可保留、移除或替换附件；旧附件版本留存数据库供追溯，操作日志不保存文件正文。
- **计时流程：**PENDING待初审 → FIRST_APPROVED待终审 → APPROVED已通过；待初审和待终审均不计时。管理员只能初审，超管终审才在同一事务生成原有排班、考勤、服务记录。未设置征集管理员的业务保留超管直接审批入口，兼容历史征集。打回必须说明原因，开放期间可修改后重报。审批版本与重复提交检查防止重复入账。
- **超管二次更正：**已通过或已打回申报可附原因更正通过/打回结果，也可更正认定分钟数（0至1440）；撤销通过会冲正时长，再次通过复用原记录，不重复记账。不扣信用分。保留历次初审、终审和更正记录。
- **截止和结束：**服务日期范围与申报截止日期分开；截止日当天仍可补报范围内的实际服务，翌日自动结束并通知，停机后启动补处理。管理员/超管也可手动结束。结束后禁止新增/重报，已经提交的记录继续审批。历史征集截止日期为空，不自动结束，可手动结束。
- **收件箱：**三种身份均有入口、未读角标、仅看未读、单条/全部已读和相关页面跳转。通知覆盖新申请及结果、征集范围申请、征集发布/结束、初审报送、终审/更正，以及密码重置、人工考勤/时长/信用调整和临时服务安排。每人仅看本人通知，不回填升级前旧消息；原申请页面仍保留历史记录。重复业务操作不重复通知。

新增接口：`GET /collection-management`、`PUT /collection-managers/{admin_id}`、`POST /collection-scope-requests`及其`/{request_id}/decision`、`POST /hour-collections/{collection_id}/close`、`POST /hour-submissions/{submission_id}/correction`、`GET /hour-submissions/{submission_id}/attachments/{attachment_id}`、`GET /inbox`、`POST /inbox/read-all`及`POST /inbox/{notice_id}/read`。旧征集/申报接口增加可选截止日期或附件字段。附件内容仅独立鉴权下载返回。

增量迁移模块`collection_governance_schema`，标记`collection_governance_v1`。新增`collection_manager`、`collection_scope_request`、`submission_attachment`、`submission_review`、`inbox_notice`五表，现共36表；仅为原征集、申报表增加列，旧ID、历史分钟和信用流水不重写。迁移前自动备份；正式迁移需先在副本核验原表指纹及重复运行。验证记录位于项目根`.work/governance-*.log`、`.work/governance-ui-smoke.json`、`.work/governance-upgrade-verification.json`；界面截图在`outputs/governance-20261026/`。

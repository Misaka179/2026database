# 业务管理模块说明

本文说明「业务管理」模块当前的架构：三层负责人、权限判定、页面分层、名单导入与成员移出。接口路径、字段与枚举以代码为准。

## 一、模块边界

- 负责：业务（business）、班次/时段（service_slot）、小组（business_group）、成员归属（slot_member / group_member / business_member）、名单导入批次、成员移出。
- 不负责：信用分与停用、退队审批（`student.status='QUIT'` 走审批流）、时长结算、征集内容本身（只提供入口与范围）。

## 二、数据模型

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `business` | 业务 | `kind`（FIXED / WEEKLY / EVENT）、`status`、`total_manager_admin_id`（业务总负责人，可空）；`manager_admin_id`、`manager_scope` 已删除 |
| `service_slot` | 班次/时段 | `business_id`、`weekday`、`start_time`、`end_time`、`manager_admin_id`（时段负责人）、`need_num`（建议人数，可空）、`schedule_kind` |
| `business_group` | 小组 | `business_id`、`name` |
| `slot_member` | 班次成员 | `slot_id`、`student_id` |
| `group_member` | 小组成员 | `group_id`、`student_id`、`effective_from`、`effective_until` |
| `business_member` | 业务级成员（无班次） | `business_id`、`student_id`、`effective_from`、`effective_until` |

`service_slot` 不设启用/停用状态：时段只要存在于目录中就视为可用，不再需要的时段直接删除，避免“停用后从页面消失、又找不到恢复入口”的死路。
| `leader_scope` | 分队负责人 | `business_id` + `weekday` 唯一；`admin_id`（NORMAL 管理员账号） |
| `member_import` | 导入批次 | `scope_kind`（BUSINESS / GROUP / SLOT）、`scope_id`、`imported_count`、`skipped_count`、`removed_slots`、`reverted_at` |
| `member_import_row` | 导入明细 | `batch_id`、`sheet_name`、`row_no`、`student_id`、`business_id`、`group_id`、`slot_id`、`created_account` |

新增列全部走 `app/directory_schema.py`、`app/business_schema.py` 的 `SHOW COLUMNS ... LIKE %s` + `ALTER TABLE ADD` 幂等迁移，旧库不需要重建。

## 三、三层负责人

三层相互独立，任何一层都不覆盖另外两层；三类负责人都必须是 `NORMAL` 管理员账号，`LEAD` 身份与角色已取消：

```
业务总负责人  business.total_manager_admin_id          （整个业务）
   └─ 分队负责人  leader_scope(business_id, weekday)  （业务 × 星期）
   └─ 时段负责人  service_slot.manager_admin_id       （单个班次）
```

| 层级 | 存储 | 任命给谁 | 权限范围 |
| --- | --- | --- | --- |
| 业务总负责人 | `business.total_manager_admin_id` | 普通管理员（NORMAL） | 本业务全部时段、成员、考勤、时长与信用；改时段与建议人数、建小组、调成员、更改归属、导入名单、发布/关闭征集、审核征集、二次更正审批记录 |
| 分队负责人 | `leader_scope.admin_id` | 普通管理员（NORMAL） | 本业务本周次的查询导出、考勤、时段管理员与建议人数、密码重置、更改归属、服务时长/信用查看、退队审核、日报；**不拥有征集权** |
| 时段负责人 | `service_slot.manager_admin_id` | 普通管理员（NORMAL） | 该班次的日常考勤、请假、换班、时长、成员更改归属、服务时长/信用查看；**不拥有征集权** |

规则：

- 一个管理员全局只能有一个生效任命，业务总负责人、分队负责人、时段负责人三类互斥。
- 业务总负责人只能由超管任命（`PUT /businesses/{id}/owner`），且不能自封。
- 分队负责人由超管或该业务总负责人任命（`PUT /businesses/{id}/leaders/{weekday}`）。
- 时段负责人与建议人数由超管或该业务总负责人设置（`PATCH /slots/{slot_id}`）。
- 三层都允许为空。业务总负责人为空时，该业务由超管直接管理；需要业务侧发征集或审核征集时，再给对应业务任命负责人即可，不要求全量任命。

## 四、权限判定

- `owner_of_business(c, business_id)`：只读 `business.total_manager_admin_id`，唯一口径。
- `require_business_owner(c, a, business_id)`：超管放行；普通管理员必须是该业务总负责人，否则 403。
- `scope(a, row)`：超管全通；普通管理员允许「该班次时段负责人」或「该业务总负责人」；学生仅本人。
- `businesses()` 返回 `can_manage`（`SUPER` 或业务总负责人）、`can_collect_all` / `can_collect`（征集相关，见第十节）。

| 动作 | 超管 | 业务总负责人 | 时段负责人 | 分队负责人 |
| --- | --- | --- | --- | --- |
| 查看本业务时段、成员、考勤、时长 | 可 | 可 | 仅本班次 | 仅本周次 |
| 添加/修改/停用时段与建议人数 | 可 | 可 | 否 | 否 |
| 建小组、调整小组成员 | 可 | 可 | 否 | 否 |
| 名单导入（班次/小组） | 可 | 可 | 否 | 否 |
| 撤销导入批次 | 可 | 可（限 7 天） | 否 | 否 |
| 更改队员归属（含「无归属」） | 可 | 可（队员在范围内，目标不受限） | 可（队员在范围内，目标不受限） | 可（队员在范围内，目标不受限） |
| 发布/关闭本业务征集 | 可 | 可 | 否 | 否 |
| 审核本业务征集申报 | 可 | 可 | 否 | 否 |
| 二次更正已审批的征集记录 | 可 | 可 | 否 | 否 |
| 设置业务总负责人 | 可 | 否 | 否 | 否 |
| 设置分队负责人 | 可 | 可（本业务） | 否 | 否 |
| 设置时段负责人与建议人数 | 可 | 可（本业务） | 否 | 否 |
| 改业务名、归档业务 | 可 | 否 | 否 | 否 |
| 负责范围内退队审核 | 可 | 可 | 可 | 可 |
| 负责范围内服务时长/信用查看 | 可 | 可 | 可 | 可 |
| 停用队员、手动调整信用分 | 可 | 否 | 否 | 否 |

## 五、页面分层与入口

| 层级 | 页面 | 渲染函数 | 主要按钮 |
| --- | --- | --- | --- |
| 根 | 业务列表 | `renderBusinessListEnhanced` | 进入业务 |
| 二级 | 班次列表 | `renderBusinessSlots` | 设置总负责人、Excel 导入、导入记录、添加时段 |
| 二级 | 小组列表 | `renderBusinessGroups` | 设置总负责人、Excel 导入、导入记录、添加小组 |
| 三级 | 班次详情 | `renderSlotMembers` | 导入本班次、名单行内「更改归属」 |
| 三级 | 小组详情 | `renderGroupMembers` | 导入本小组成员、名单行内「更改归属」、设置负责人 |

- 固定业务（FIXED，如咨询服务、美育）没有名单导入，只有时段与归属；名单导入只服务非固定业务与小组。
- 动作统一由 `web/app.js` 的点击分发转给 `businessAction(name, id, kind, studentId)` / `directoryAction(name, id, kind)`，新动作只需要在两处登记。
- 导入弹窗由 `web/import-ui.js` 提供，二级入口传 `kind=BUSINESS`，三级班次传 `kind=SLOT`，三级小组传 `kind=GROUP`。

## 六、Excel 导入链路

```
上传 xlsx → 解析（import_common） → 工作表映射 → 判定 → 预览 → 显式确认 → 提交事务 → 批次记录 → 可撤销
```

### 1. 入口与接口

| 接口 | 用途 | 适用范围 |
| --- | --- | --- |
| `POST /students/import` | 固定业务名单导入 | 固定业务；传 `slot_id` 时全员归该班次并忽略「分类」列，不传则按表格中的分类/时段列映射 |
| `POST /member-imports` | 非固定业务/小组导入 | `scope = {kind: BUSINESS/GROUP, id}`，可带 `approvals` |
| `GET /member-imports` | 导入记录列表 | 本业务总负责人或超管 |
| `GET /member-imports/{batch_id}` | 批次详情与可否撤销 | 同上 |
| `POST /member-imports/{batch_id}/revert` | 撤销整批 | 同上，限 7 天 |

两个入口共用同一张 `member_import` 批次表与同一套解析、判定逻辑。

### 2. 解析

- 统一限额：文件 8MB、压缩包 2000 个部件、解包后 40MB、单表 10000 行 / 100 列。
- 表头规则：**任意一行同时含「姓名」「学号」两列即视为表头**；一张工作表里可以有多段表头，重复表头会重新起一段。
- 必填列：姓名、学号；学院可选；分类 / 时段 / 小组列可选用作提示。
- 学号按文本处理；数字型学号若出现小数或超出 15 位，按精度不可靠报错，不猜。

### 3. 判定

同一学号先合并成一个人，再按下列规则定档：

| 情况 | 结果 | 是否需要人工确认 |
| --- | --- | --- |
| 系统里没有这个学号 | 通过，新建账号与归属 | 否 |
| 学号存在且姓名一致、在队 | 通过，只加归属 | 否 |
| 信用归零停用（`disabled_by_credit`）或已停用（`DISABLED`） | **硬跳过**，不导入 | 否 |
| 学号存在但姓名不一致 | 待确认 | 是（确认后按导入，不覆盖系统姓名） |
| 已退队（QUIT） | 待确认 | 是（确认后恢复在队） |
| 同一学号出现多个姓名 | 待确认 | 是 |
| 姓名或学号是公式且无缓存值 | 待确认 | 是 |
| 学号格式非法、缺姓名、姓名/学院超长 | 报错，阻断提交 | 否 |

- 待确认行默认**不导入**，只有前端勾选或 `approvals` 显式确认后才写入；不是错误，不会中断整批。
- 新学号但与系统某人同名：直接建新账号，不提示、不汇总。

### 4. 提交

- 只建账号与归属，不计时、不生成排班。
- 单事务写入账号、业务/小组归属、批次与明细，并写审计 `IMPORT_MEMBERS`。
- 有新建账号时必须填 8–128 字符初始密码。
- `request_hash` 由文件哈希 + 映射 + 确认项 + 跳过项算出，同一请求重复提交会返回原批次，不重复写入。

### 5. 撤销

- 限导入后 7 天内，超管或该批次涉及业务的负责人可撤销；已撤销的批次再撤销返回 409。
- 撤销内容：本批建立的归属、本批新建且无其他归属与历史的账号、被本批挤出并记录在 `removed_slots` 的时段（自动加回）。
- 账号是否真删先查引用：只要还存在排班、时长、申请、管理员身份等历史，就保留账号，只撤回本次归属，返回里用 `kept_accounts` 区分。
- 写审计 `REVERT_MEMBER_IMPORT`，批次打 `reverted_at` 后不可再次撤销。

## 七、成员移出

| 层级 | 接口 | 语义 |
| --- | --- | --- |
| 班次 | `DELETE /slots/{slot_id}/members/{student_id}` | 只移除这一个班次的归属；取消该班次未来排班（`cancel_reason=MEMBERSHIP`）、相关请假、指向该班次的待审换班；同步学期；写审计 `REMOVE_SLOT_MEMBER`；不删账号、不改其他班次 |
| 小组 | `PUT /business-groups/{group_id}/members/{student_id}`（`active=false`） | 按 `effective_date` 收口 `group_member.effective_until`，不追改历史；`effective_date` 不能早于今天 |

- 班次移出要求操作者是超管或该业务总负责人；队员不在本班次返回 422。
- 业务级退出（退队）走「学生提交 → 有唯一分队负责人时该负责人一次审核，否则超管审核 → 结果抄送超管」，本模块不提供按钮。

## 九、约束与边界

- 不删除账号：只有撤销「本批新建且无任何历史」的账号时才会删，其余一律保留。
- 负责人可空；为空不影响系统运行，只影响该业务的业务侧操作权限。
- 固定业务不能用名单导入，必须走时段归属。
- 业务已划分小组时，导入必须指定小组，不能把整批塞进业务级。
- 归属调整不追溯历史：`effective_date` 不早于今天，未来排班才取消。
- 归档业务前有影响检查，存在待处理事项会被阻塞。

## 十、征集权限来源（方案 A：只归业务总负责人）

- 征集权只来自 `business.total_manager_admin_id`：业务总负责人拥有本业务全部小组的发布、关闭、名单选择、审核与二次更正权限。
- `leader_scope.admin_id`（分队负责人）与 `service_slot.manager_admin_id`（时段负责人）**均不拥有征集权**：不能发起、不能管理、不能审核，征集列表也不向他们展示。
- `business.manager_admin_id` 已删除，不再参与征集判定。
- 没有业务总负责人时，超管直接发布征集并兜底审核。
- 审核只有一次：普通业务总负责人或超管在 `PENDING` 状态直接决定 `APPROVED` / `REJECTED`，不再有 `FIRST_APPROVED` 中间态。二次更正只开放给业务总负责人和超管。
- 咨询服务为 `FIXED`，不开放时长征集。
- 咨询服务为 `FIXED`，不开放时长征集。
- 旧「征集权限配置」页、管理员侧「申请获得征集权限」页，以及 `collection_manager` / `collection_group_manager` / `collection_scope_request` 三张表与旧数据已删除；列表过滤、候选人员、小组查看均改用业务总负责人口径。

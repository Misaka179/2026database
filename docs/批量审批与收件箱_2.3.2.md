# 批量审批、小时申报与收件箱（2.3.2）

更新日期：2026-10-26。保留原架构与数据库记账链，本次不增加表、不改写历史记录。

## 超级管理员批量通过

进入“时长与信用 → 时长征集”，在每次征集内勾选可终审条目，或点击“全选可审批条目”，然后点击“批量通过”。确认框展示征集名称、人数、条数和合计小时，可填写审批说明。

不同征集的选择相互独立；需要普通管理员初审但尚未完成的申报不可选。没有普通征集管理员的业务仍允许超管直接审批。普通管理员不显示批量终审入口。

后台逐项校验范围、状态和版本，在同一事务内提交审批、入账、日志和通知。任一条目失败整批回滚，错误信息列出相关申报编号；失败保留选择，刷新后重新核对。重复提交相同版本的已成功审批不会重复计时。没有新增批量打回。

接口：`POST /hour-collections/{collection_id}/approve-batch`，请求含`items:[{submission_id,expected_revision}]`及可选`reason`，返回本次通过数`approved`和重复请求数`replayed`。单条与批量复用同一个事务内审批实现，批量不循环调用各自提交事务的单条HTTP接口。

## 所有后续申报统一按小时

志愿者填写和修改重报统一使用“申报时长（小时）”，以0.5小时递增、至少0.5小时，最大24小时。API和数据库仍存整数分钟；前后端均校验，不自动四舍五入。

此规则同样适用于旧征集的新申报及重报，替代2.3.1中旧征集仍按分钟申报的兼容行为。原事项上下限不改写：申报表单的有效下限向上取半小时，上限向下取半小时。例如原1—86分钟可填0.5或1.0小时。不存在合法值时禁用提交，提示联系管理员重新发布事项。

已提交、已审批和已入账历史不自动改写。历史申报重新填写时原值按小时回显；不符合半小时的值必须由本人改为合法值才能重新提交，不自动取整。原附件、日期限制及两级审批仍有效。

## 收件箱批量已读

三种身份均可勾选本人未读通知，已读通知不提供勾选框。可“全选当前列表未读通知”“取消全选”，再点击“批量标为已读”。原有单条已读、全部已读和查看相关记录入口保留，没有新增删除功能。

全选只作用于当前已加载的列表。加载更多保留选择，但新加载通知不会自动选中；切换筛选、刷新、离开页面或退出登录清空选择。处理中禁用重复操作，失败保留选择；成功刷新列表和未读角标，仅看未读时已处理通知从列表移除。

接口：`POST /inbox/read-batch`，请求`notice_ids`数组。后台核对所有通知属于当前账号后，在同一事务内标记。已读通知重复处理保留首次时间；包含他人或不存在的通知整批拒绝。

## 1. 设计目标与硬约束

### 1.1 目标

1. **信息效率优先**：管理员每天要处理排班、考勤、审批、时长修正；志愿者主要在手机上查自己的排班、时长、信用。首屏必须直接给出"我现在要做什么"。
2. **层级可读**：当前页面标题、区块标题、表格正文、辅助说明的字号差异过小，长页面容易糊成一片。新版用 6 级排版阶梯 + 区块留白建立层级。
3. **状态可信**：审批中 / 已通过 / 已驳回 / 请假 / 缺勤等状态必须"颜色 + 文字 + 形状"三重编码，不能只靠颜色。
4. **移动端可用**：志愿者 80% 以上访问发生在手机；宽表格要在手机上真正可用，而不是只能左右拖动。
5. **可维护**：把 22KB 单文件 CSS 拆成"令牌 → 基础 → 组件 → 页面"四层，后续新增页面不再复制粘贴。
6. **零外部依赖**：不联网也能完整显示（学校机房、离线演示场景）。不引入字体 CDN、图标库、CSS 框架。

### 1.2 硬约束（不可违反）

| 约束 | 说明 |
|---|---|
| 无构建步骤 | 不允许 npm / 打包器；浏览器直接加载源码 |
| 无 CDN / 远程字体 | 页面加载不依赖外网；字体使用系统中文字体栈 |
| 无图片资源 | 插图与图标一律使用**内联 SVG**（可在 JS 字符串中定义）或纯 CSS 图形 |
| 原生 `<dialog>` | 继续使用浏览器原生模态对话框，保证焦点管理与无障碍 |
| 接口协议不变 | 前端只消费现有 API；不扩展后端尚未支持的业务 |
| 中文优先 | 业务文案简体中文；API 字段名与枚举值保持原样 |
| 令牌页 | `/docs` 接口文档页与工作台共用同一套颜色令牌 |
| 契约钩子不变 | 见 11.5「契约冻结清单」，改样式不得改这些 id / 属性 / 文案 |

## 3. 设计方向（视觉概念）

### 3.1 三个候选方向

| 方向 | 气质 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 馆藏 · 纸墨（推荐） | 安静、书卷气、公共服务 | 与"图书馆志愿服务"强绑定；低饱和不刺眼；适合长时间后台 | 需要克制，容易做得平淡，靠排版与留白取胜 | **推荐** |
| B. 学院 · 仪表盘 | 数据感、效率、偏科技 | 指标与图表突出 | 容易像通用 SaaS，丢掉图书馆身份 | 备选 |
| C. 青春 · 志愿红 | 热情、社团感 | 登录页有感染力 | 不适合每天处理 3000+ 条数据的后台；红色与错误态冲突 | 不采用 |

**最终采用 A**，并在局部吸收 B 的数据表达（指标卡、进度条、周条），在登录页吸收 C 的一点温度（文案与插图式排版，不用大红大绿）。

### 3.2 概念说明

> 「纸墨」= 底是纸、字是墨、绿是图书馆的旧书封、铜是书脊。  
> 界面像一册排版良好的馆务台账：**标题醒目但不喧哗，表格密而不乱，动作永远在它该在的位置。**

三类用户的界面语气不同但同一套语言：

- **志愿者（手机为主）**：一屏看到"我的下一班 / 本周时长 / 信用分 / 待办"。语言温暖、短句、少术语。
- **普通管理员（电脑为主）**：每天的核心是"审批 + 考勤"。以队列为单位组织，处理完一条列表自动收敛。
- **超级管理员**：配置与审计。以"表格 + 侧滑详情"为主，强调可追溯（操作日志用时间线）。

### 3.3 反例（明确不做）

- 不做营销式大图、大幅渐变、玻璃拟态。
- 不做悬浮胶囊导航、汉堡菜单套汉堡菜单。
- 不用纯黑 `#000` 与纯白背景直接对撞。
- 不用多于 1 个主色 + 1 个强调色；状态色只在状态里出现。
- 不给每个区块加阴影，阴影只用于"浮起来的东西"（对话框、抽屉、toast）。
- 不做需要鼠标悬停才出现的关键信息（触屏不可用）。

### 3.4 设计参数（沿用项目既有口径）

| 参数 | 值 | 说明 |
|---|---|---|
| 设计变化程度 | 3/5 | 有辨识度，但不夸张 |
| 动效强度 | 2/5 | 只做状态过渡与方向暗示 |
| 信息密度 | 5/5 | 后台表格保持紧凑 |
| 圆角 | 中 | 控件 8、卡片 12、对话框 16 |
| 图像 | 无 | 只有内联 SVG 线性图标 |

### 4.3 色彩使用规则（60-30-10）

- **60%**：纸色 + 白色 + 墨色（背景与文字）。
- **30%**：边框、浅底、次级灰（结构）。
- **10%**：馆藏绿（动作与激活）+ 状态色（仅状态）+ 铜色（极少量数值强调）。
- 状态色**不得**用于非状态元素（不用绿色装饰标题，不用红色做重点字）。
- 链接与主按钮同为主色；同一屏内"填充绿"主按钮最多 1 个（页面主操作），其余为描边或文字按钮。
- 选中/激活 = 浅主色底 + 主色文字 + 左侧 3px 主色指示条（导航），不用整块实色。

| `--fs-14` | 14px / 1.65 | 页面正文（基准） |

### 4.5 间距（4px 基准）

`--space-1..--space-12` = 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80 / 96。

| 场景 | 值 |
|---|---|
| 控件内边距 | 横向 12–16，纵向 8–10 |
| 卡片内边距 | 20–24 |
| 区块间距 | 24–32 |
| 页面内容区 | 桌面 32–40，平板 24，手机 16 |
| 表格单元格 | 横向 16–20，纵向 10–12（行高 44） |

### 4.6 圆角与描边

描边统一 `1px solid var(--color-border)`；不用 2px 以上边框表达层级（用底色与间距）。

## 5. 组件规范

组件分三层：**基础组件**（按钮、输入、徽章…）、**复合组件**（工具栏、页头、表格块、指标卡、抽屉…）、**模板**（页面骨架，见第 6 节）。  
命名约定：**现有 class 一律不改名**；新增结构用 `ui-` 前缀（如 `ui-page-header`、`ui-toolbar`），状态用 `is-` 前缀（`is-loading`、`is-active`），不复用业务样式类做结构类。

### 5.1 按钮 `button` / `.btn`

| 变体 | class | 底色 | 文字 | 用在哪 |
|---|---|---|---|---|
| 主按钮 | `.btn.primary` | 主色 | 白 | 每屏 1 个：提交、创建、确认 |
| 次按钮 | `.btn` | 白 / 悬停浅灰 | 墨色 | 取消、导出、刷新 |
| 幽灵 | `.btn.ghost` | 透明 | 主色 | 区块内次要动作 |
| 危险 | `.btn.danger` | 透明 + 危险描边 → 悬停填充 | 危险色 | 删除、停用、驳回 |
| 文字 | `.text-button` | 无 | 主色 | 表格行内操作 |
| 图标 | `.ui-icon-button` | 无 | 墨色 | 主题、菜单、关闭 |

尺寸：`sm` 32px / `md` 40px（默认）/ `lg` 44px（移动端与登录）。  
状态：默认 / 悬停 / 按下 / 焦点（3px 外环 + 2px 间距）/ 禁用（`opacity:.45` + `not-allowed`）/ 忙碌（左侧 14px 旋转指示 + 文案不变，宽度锁定避免跳动）。  
规则：按钮内文字≤6 个汉字；表格行内操作最多显示 2 个，其余收进"更多"。移动端行内操作改为 44px 触摸区。

### 5.2 表单控件

| 组件 | 规格 |
|---|---|
| 输入框 `.field input` | 高 40（移动 44），内边距 10×12，圆角 8，1px 边框 |
| 选择框 `select` | 同上，右侧自绘 chevron（CSS 背景，不用图片） |
| 文本域 `textarea` | 最小 96px，可纵向拉伸，最大 240px |
| 搜索框 | 左侧内联 SVG 放大镜，`type="search"`，清除按钮原生 |
| 焦点态 | 边框转主色 + `box-shadow: 0 0 0 3px var(--color-primary-soft)` |
| 错误态 | 边框危险色 + 下方 12px 红色说明（`aria-describedby` 指向） |
| 必填 | 标签后 11px muted「必填」；不滥用星号 |
| 帮助文本 | 12px muted，位于控件下方 |
| 分组 | `.form-grid` 两列（≥768），单列（<768）；`.field.full` 跨两列 |

### 5.3 表格 `.ui-table`（升级现有 `table`）

- 表头：12px、500、`--color-bg-sunken` 底、下边框、**粘性定位**（滚动时吸顶，`position: sticky; top: 0`）。
- 行高：默认 44px；两行信息（主 + 次）56px（沿用现有 `td strong` + `td small` 结构）。
- 悬停：`--color-surface-hover`；选中：`--color-primary-soft` + 左侧 3px 主色条。
- 数字列：右对齐 + tabular-nums；状态列：徽章；操作列：右对齐，固定最小宽。
- 空态：表格区域整体替换为 `.empty`（见 5.9），**不显示表头**。
- 加载：保留表头 + 3 行骨架。
- 移动端（<768）：切换为"卡片列表"模式，每个 `<tr>` 变成一张小卡，`<td>` 用 `data-label` 生成左侧标签（见 7.3）。

### 5.4 状态徽章 `.badge`（重构）

统一为「圆点 + 文字」或「浅底 + 文字」，圆角 4px，11–12px，`white-space: nowrap`。

| 语义 class | 底色 | 文字 | 对应状态 |
|---|---|---|---|
| `.badge.good` | success-soft | success | 有效、正常出勤、已通过、已完成 |
| `.badge.warning` | warning-soft | warning | 迟到、待补设置、待审核 |
| `.badge.danger` | danger-soft | danger | 缺勤、已驳回、已停用、已退队 |
| `.badge.pending` | 透明 + 虚线边框 | secondary | 待处理、待审核 |
| `.badge.info` | info-soft | info | 进行中、已结算 |
| `.badge.neutral` | surface-hover | muted | 已取消、历史版本、未登记 |

规则：**颜色不单独承担语义**，徽章内必须有文字；同一页面同一状态只用一种视觉。

### 5.5 页头 `.ui-page-header`

```
┌──────────────────────────────────────────────────────────────┐
│ 面包屑：管理工作台 / 排班与考勤                                │
│ 页面标题（28px 600）                        [次要操作] [主操作] │
│ 一句话说明（13px 次级）                                       │
└──────────────────────────────────────────────────────────────┘
```

- 与顶栏的 `#breadcrumb-title` 保持联动（现有逻辑不变）。
- 主操作靠右，最多 1 个填充按钮 + 1 个描边按钮。
- 页面标题与说明**必须来自页面定义**，不再在每页重复写死文案（收敛到 `pages` 配置表）。

### 5.6 工具栏 `.ui-toolbar`

- 左：搜索框 + 筛选（下拉/日期）+ 已选筛选 chips（带"清除"）。
- 右：刷新、导出、批量操作（选中≥1 时出现）。
- 换行规则：宽度不足时整组换行，不压缩输入框到 80px 以下。
- 结果计数：`共 42 条`，12px muted，位于工具栏右侧或表格上方。

### 5.7 指标卡 `.metric`（升级）

```
标签（12px muted）
主数值（36px 600，tabular-nums）  单位（12px）
脚注（11px muted）：较上周 +3 / 已结算至 10-26
```

- 桌面 4 列；≤1100 两列；≤600 两列紧凑。
- 数值不使用铜色，只有"累计/荣誉类"（如总时长）允许铜色 + 小图标。
- 卡片之间用 1px 分隔，不用阴影。

### 5.8 对话框 `.ui-dialog` 与抽屉 `.ui-drawer`

| 形态 | 尺寸 | 用途 |
|---|---|---|
| 小对话框 | 480px | 确认、单字段原因 |
| 中对话框 | 640px（默认） | 常规表单（请假、考勤、调分） |
| 大对话框 | 880px | 多区块表单（征集发布、导入预览） |
| 宽对话框 | 1100px | 需要并排对比的复杂表单 |
| 右侧抽屉 | `min(520px, 92vw)`，全高 | 详情、审批记录、附件预览、日志详情 |

规范：

- 结构：`.dialog-header`（标题 18px + 副标题 12px + 关闭）／`.dialog-body`（滚动区）／`.dialog-footer`（右对齐，主操作在右）。
- 头部与底部**固定**，只有 body 滚动；`max-height: calc(100dvh - 48px)`。
- 遮罩：`--color-overlay`，**不使用 backdrop-filter**（低端平板掉帧）。
- 抽屉：从右侧滑入 180ms，`border-radius` 只保留左侧两个角，遮罩点击关闭；移动端变全屏。
- 关闭保护：表单有改动时点遮罩先确认；提交中禁用关闭按钮（沿用现有 `setModalBusy`）。
- 焦点：打开时聚焦第一个输入或标题；关闭后回到触发按钮（现有 `previousFocus` 逻辑保留）。
- 危险确认：标题用问句，主按钮为危险色，必须输入原因（如退队、驳回、停用）。

### 5.9 空态 `.empty` / 加载 `.loading` / 骨架 `.ui-skeleton`

- 空态：内联 SVG 线性插图（64×64，主色 30% 透明度）+ 标题 14px 600 + 说明 12px muted（≤2 行）+ 可选主操作按钮。
- 加载：页面级用骨架（标题条 + 4 行表格条）；操作级用按钮内旋转指示；**不使用**"正在读取…"纯文字超过 300ms 仍无内容。
- 骨架微光：仅 `prefers-reduced-motion: no-preference` 时启用，1.4s 循环，低对比。

### 5.10 通知 Toast `.toast`

- 位置：桌面右下（距底 24，距右 24）；移动端底部居中、宽度 `calc(100vw - 32px)`。
- 类型：`success`（默认）/ `.error` / `.warning` / `.info`，左侧 3px 色条 + 图标。
- 时长：成功 3s，错误 6s（可手动关闭）；最多同时 3 条，超出挤掉最旧。
- 无障碍：容器 `role="status" aria-live="polite"`；错误用 `role="alert"`。
- 内容：一句话结论 +（可选）一句下一步，不打印堆栈或英文异常。

### 5.11 通知条 `.notice`（页面内）

- 四类：info / success / warning / error；左侧 3px 色条 + 浅底。
- 用于"停机说明""未配置负责人""导入有 N 条待核对"等**持续存在**的提示。
- 可关闭；关闭状态记入 `localStorage`（按键名），避免每次刷新重复打扰。

### 5.12 标签页 `.tabs` / `.tab`

- 胶囊型分段控件；激活 = 浅主色底 + 主色文字 + 600。
- 键盘：方向键切换（`role="tablist"` 已有），`aria-selected` 保留。
- 超过 5 个时横向滚动并显示边缘渐隐。

### 5.13 步骤条 `.ui-steps`（新增，用于导入向导）

```
① 上传文件 ── ② 预览与校验 ── ③ 确认导入
```

- 当前步主色实心圆，完成步主色对勾，未开始步描边灰。
- 每步下方 11px 说明；错误数用 danger 徽章挂在步骤上。
- 移动端改为"第 2 / 3 步 · 预览与校验"单行 + 进度条。

### 5.14 侧栏 `.sidebar` 与顶栏 `.topbar`（升级）

**侧栏（264px）**

```
[图] 图书馆志愿服务            <- 品牌 40px 高
    志愿队管理工作台

工作概览                        <- 固定项，图标 + 文字
收件箱                 (3)      <- 固定项 + 未读徽章

业务与人员            ⌄        <- 分组，可折叠（保留现有 localStorage 记忆）
  负责人工作台                  <- 仅负责人（LEAD）可见
  业务管理                      <- 分队负责人、总负责人、小组负责人都在这三个页面内设置
  ...
```

- 激活项：浅主色底 + 主色文字 + 左侧 3px 主色条。
- 图标：内联 SVG 18px 线性图标（替代现在的文字符号），颜色继承，`aria-hidden`。
- 分组标题 12px muted，可折叠，折叠状态记忆（现有 `nav-folds-<role>` 保留）。
- 字号统一 +1px（较 v2.4.0）：导航项 **14px**、子项 **13px**、分组标题 12px、底部链接 13px；行高 40px，保证可读性与点击面积。
- 底部：接口文档入口 + 用户头像（姓名末两字）+ 角色 + 退出。
- 移动端：抽屉式，遮罩 + 焦点圈定；`菜单` 按钮保留。

**顶栏（64px，粘性）**

- 左：移动端菜单按钮 + 面包屑（`管理工作台 / 当前页`）。
- 右：连接状态（圆点 + "服务正常/中断"）+ 主题切换（三态循环：跟随系统 → 浅色 → 深色）。
- 断网/服务中断时圆点转危险色并在顶栏下方出现一条 `.notice.error`（可手动关闭）。

| 浅绿 | 焦点环 `rgba(94,146,118,.28)`、chip 圆点 `#A9D3B6`、主按钮渐变 `#3F7359 → #2D5B4B`、说明图标 |
| 文字 | 主视觉 `#F2F7F3` + `rgba(...,.72)` 次级；表单 `#1C2723` / `#6D7771` |

**规格**

- 栅格：左侧 1.08fr、右侧最小 430px；≥1680px 时整体居中，最大宽 1680px。
- 字号：在上一版登录页基础上**整体 +1px**（输入 15、标签 14、说明 14、副标题 12.5、主标题 clamp 2.1–3rem、控件高 52）。
- 控件：图标内嵌左侧（19px），圆角 13，聚焦时主色描边 + 4px 浅绿外环；密码「显示/隐藏」在框内右侧；身份下拉右侧 chevron。
- 模块：身份、账号、密码（标签右侧「忘记密码？」）、登录有效期 + 联系入口、渐变主按钮、分隔线「其他操作」、找回/修改密码链接、页脚；左栏 4 条功能说明**纵向 4 行**排布（图标 + 标题 + 一句话说明），三条数据在底部等分，整体在高度方向均匀分布。
- 登录页不展示安全/隐私声明（按评审意见移除，避免在登录页做笼统承诺）；实现事实（PBKDF2-SHA256、令牌 1 小时、仅监听 127.0.0.1）记录在 `docs/validation.md`。
- 移动端：≤900 隐藏左侧主视觉，表单区顶部显示紧凑品牌；≤480 控件 50px、主按钮 52px；横向不溢出。
- 深色主题：右侧转深色底，控件深底浅字，按钮转浅绿渐变配深色字（对比度 9:1）。
- **视口高度自适应**：桌面端以 `100dvh` 布局，按 ≤900 / ≤800 / ≤700px 三档压缩字号、间距、控件高度与非关键说明；1366×768 与 1536×864 实测一屏放下，低于 700px 才允许页面滚动。

## 7. 响应式与移动端

### 7.1 断点

| 断点 | 名称 | 布局 |
|---|---|---|
| ≥1440 | 宽屏 | 侧栏 264 + 内容 1440 居中；概览两栏 |
| 1200–1439 | 桌面 | 侧栏 264；内容铺满 |
| 1024–1199 | 小桌面 | 侧栏 232；概览改单栏 |
| 768–1023 | 平板 | 侧栏收起为抽屉；工具栏换行；表格卡片化开始 |
| ≤767 | 手机 | 单列；页头操作下沉；表格卡片化；对话框全屏 |
| ≤480 | 小屏 | 按钮全宽；指标卡两列紧凑 |

> 登录 / 密码页在宽度断点之外还有**视口高度断点**：≤900、≤800、≤700px 三档（见 §6.1），保证 1366×768 笔记本一屏放下。

### 7.2 移动端首屏优先级

- 志愿者：下一班 > 本周时长 > 待办 > 信用分。
- 管理员：待审批数 > 今日排班 > 未读。
- 导航：抽屉 + 遮罩，当前分组默认展开。

### 7.3 表格在手机上的处理

三种方案对比：

| 方案 | 成本 | 体验 | 结论 |
|---|---|---|---|
| A 横向滚动（现状） | 最低 | 差（看不到操作列） | 保留为兜底 |
| B 粘性首列 + 横向滚动 | 低 | 中 | 所有表格可用 |
| C 卡片化（`<tr>` → 卡片） | 中 | 好 | **关键页启用** |

**决策：B + C 组合**。`schedules`、`applications`、`hours`、`credit`、`inbox`、`members` 6 个高频页面启用 C；其余表格用 B。  
实现：渲染 `<td>` 时补 `data-label="列名"`（由 `table()` 模板统一注入），移动端 CSS 将 `tr` 变 `display:grid`，`td::before{content:attr(data-label)}`。

### 7.4 触摸与输入

- 所有可点区域 ≥44×44。
- 不用 hover 才能看到的信息；`select` 使用原生控件（手机上系统选择器体验最好）。
- 日期输入使用原生 `type="date"`（已有）。
- 长表单分区块；键盘弹出时页脚按钮保持可见（`dvh` 单位，不用 `vh`）。

## 8. 可访问性（WCAG 2.1 AA）

| 项 | 规范 |
|---|---|
| 对比度 | 正文 ≥4.5:1，大字 ≥3:1（本方案全部达标，见 4.1/4.2） |
| 焦点 | 全站 `:focus-visible` 3px 主色外环 + 2px 间距，禁止 `outline:none` |
| 键盘 | Tab 顺序 = 视觉顺序；对话框焦点圈定；Esc 关闭；跳转链接 `#main` |
| 语义 | `nav`/`main`/`header`/`table` 正确使用；表头 `<th scope="col">`（已用） |
| 图标 | 全部 `aria-hidden="true"` 或提供 `aria-label`；不用 emoji 承担语义 |

## 10. 交互与反馈模式

### 10.1 三类反馈的层级

| 层级 | 组件 | 用于 |
|---|---|---|
| 即时 | 按钮内旋转 / 行内提示 | 单次操作 <1s |
| 局部 | 区块骨架 / 行高亮 / 内联 `.notice` | 列表刷新、局部校验 |
| 全局 | toast | 操作结果 |

原则：**同一操作只给一层反馈**；成功不弹对话框，错误不只用 toast（表单错误必须就地显示）。

### 10.2 破坏性操作

删除/停用/驳回/退队：二次确认对话框 → 必须填写原因（可配置必填）→ 成功后 toast + 列表刷新 + 该行 1.2s 高亮。  
不可撤销的操作（退队确认、停用账号）在确认框里用危险色主按钮，文案写清后果。

### 10.3 批量操作

选中 ≥1 项后工具栏浮出"已选 N 项" + 操作按钮 + "取消选择"。批量操作为空选中时按钮禁用并提示。执行后保留选中状态下一次操作（同类型），切换页面/标签时清空（沿用现有 `state.inboxSelected` 清理逻辑）。

### 10.4 长表单

- 分区块（`<fieldset>` + 区块标题）或分步骤。
- 提交失败：滚动到第一个错误字段并聚焦，保留已填内容（现有逻辑）。
- 底部操作区粘性；"取消"在左、"提交"在右。

### 10.5 主题切换

- 三态：跟随系统（默认）/ 浅色 / 深色，按钮文字显示"下一次切换到的目标"。
- 存储键沿用 `volunteer_theme`，值 `system|light|dark`；兼容旧值（`light`/`dark`）与旧逻辑（无值时跟随系统）。
- 页面加载前由 `tokens.css` 内联脚本或 `index.html` 头部小脚本应用，避免闪白。

**Node VM 桩的 10 条隐形红线**
1. `app.js` 必须以**独立一行** `start();` 结尾（测试用正则摘掉启动）。
2. 必须是经典脚本 + 全局词法作用域：**不能 ESM 化、不能 IIFE 包裹、不能新增重名顶层 `const`**。

6. 桩的 `setTimeout` 是 noop、`matchMedia` 恒 `false`；不要用定时器承担首屏必要逻辑。
7. 每个事件类型只保留最后一个监听（`listeners[type]=callback`），不要把关键逻辑挂在会被覆盖的同类监听上。
8. `FormData` 只在测试的 `actionForm()` 里注入；`validate()` 在测试里拿到空 `querySelectorAll`，**表单校验本身无自动化覆盖**，改动后必须手工验证。
9. 测试按全局名调用函数（见上），任何"模块化整理"都要保留全局别名。
10. 桩无 `dialog.close` 事件回调假设，弹窗生命周期沿用现有 `modalVersion` / `setModalBusy` 机制。

**处理方式**：重设计**不改**上述内容；若某处必须调整，同步修改 `tests/test_ui_contract.py` 并在提交说明中列出（我会逐条复核）。实施顺序上，**文案与命名冻结到最后**，优先做纯 CSS 与不涉及契约的组件升级。

### 11.9 找回 / 修改密码的接口契约（2026-11-07 历史提案）

> 本节保留当时尚未实现接口时的提案。接口现已落地，且账号/姓名精确匹配、HTTP 422、同日通知去重及改密成功退出登录等现行契约以 §15.8 为准。

当前后端只有管理员重置（`POST /students/{id}/reset-password`、`POST /admins/{id}/reset-password`），没有自助找回与自助改密。正式实现建议：

| 场景 | 接口 | 说明 |
|---|---|---|
| 忘记密码·提交申请 | `POST /auth/password/reset-request` | body：`kind/account/name/phone/reason`；写入收件箱通知管理员；返回受理号；按账号限流（10 分钟 1 次） |
| 忘记密码·查询状态 | `GET /auth/password/reset-request/{ticket}` | 只返回 `PENDING/APPROVED/REJECTED`，不返回任何密码 |
| 管理员处理 | 复用现有 `POST /students/{id}/reset-password`、`POST /admins/{id}/reset-password` | 管理员核实身份后重置，并把结果写入申请人收件箱 |
| 修改密码 | `POST /auth/password/change` | body：`current_password/new_password`；校验 8–128 位；成功后令牌版本 +1，旧令牌立即失效 |

实现要点：

- 口令哈希沿用 `app/security.hash_password`；重置与改密都必须写 `operation_log`（原因必填）。
- 忘记密码申请可复用现有收件箱机制，无需新表；若需要保存受理状态与审计，可新增 `password_reset_request` 表。
- 令牌吊销：现有令牌只含 `kind/id/exp`，建议在 payload 中加 `ver`（凭据版本），或新增 `admin/student.credential_version`，改密后自增。
- 前端：页面与路由已按本契约实现（预览）；等接口就绪后把静态表单接上，在此之前只显示「请联系管理员重置」的提示，不做假提交。

#### 登录、找回密码与改密

- 登录标题为“登录系统”，说明为“使用管理员账号或志愿者学号登录。”；保留 `#login-form`、`#login-error`、原字段名、主题存储、登录接口、键盘焦点和密码显隐契约。
- `/password` 只显示“找回密码”，主说明固定为“提交账号信息后，由管理员协助重置，并通过其他方式告知你。”；字段保持 `kind/account/name/phone/reason`，手机号和情况说明选填。
- 服务端只去除首尾空白后做同记录精确匹配：志愿者必须匹配 `student_id + name`，管理员必须匹配 `account + name`。不接受部分姓名、模糊匹配、跨身份匹配或只校验其中一项。
- 匹配失败返回 HTTP 422；志愿者文案为“学号或姓名不正确，请检查后重试。”，管理员文案为“管理员账号或姓名不正确，请检查后重试。”。失败不创建重置申请，也不写管理员收件箱通知。
- 匹配成功继续返回 `{"status":"ACCEPTED"}`，同账号同日通知保持去重；成功文案固定为“重置申请已提交。管理员处理后会通过其他方式告知你。”。“其他方式”仅指电话、即时通讯或线下联系，不暗示自动短信、邮件或站内通知。
- 工作台“修改密码”继续使用通用弹窗和 `POST /auth/password/change`。成功后保存当前身份与账号提示、清除会话、关闭弹窗并回到登录页；登录页预选身份、回填账号、聚焦密码框，显示“密码已更新，请使用新密码登录”。
- 旧 `/password#change` 显示“请登录后在工作台修改密码”，随后规范化到 `#reset`；不恢复第二套改密表单。

# 管理员设置与时段测试账号

更新：2026-09-27，API 版本 1.3.0。

## 超级管理员设置普通管理员

原有“基础资料 → 管理员 → 新增管理员”和“服务班次 → 设置负责人和容量”都只允许超级管理员操作。现在另提供从现有队员直接授权的入口。

1. 以超级管理员登录，打开“基础资料 → 志愿者”，可按完整学号查询。
2. 找到正常在队的队员，点击“设为普通管理员”。
3. 勾选其负责的固定时段并填写原因。不勾选时段只建立管理员身份；勾选会替换这些时段的原负责人，其他时段不变，也不会改变该队员自己的志愿服务归属。
4. 保存后，该队员在登录页选择“管理员”，使用学号和现有志愿者密码登录。选择“志愿者”仍可进入原来的个人工作台，历史时长、信用分、申请和归属均保留。
5. 以后调整负责时段，在“基础资料 → 服务班次”修改负责人。管理员列表显示关联队员和负责时段。

一个队员只关联一个普通管理员账号，重复提交不重复建号。已有同名独立管理员账号时拒绝覆盖。普通管理员只能管理分配的时段，不能授予管理角色或调整全队信用分；队员停用或退队后，关联管理员登录和已有会话的管理权限暂停。重新恢复正常在队状态后可继续登录。独立测试管理员不关联真实队员。

人数上限允许留空待设置，分配负责人不会擅自填充容量。已有固定队员的学期排班照常计时；手动新增排班或换入前仍须完善人数上限。

## 每个时段的测试管理员

周一至周日每天 5 个固定时段，按 35 个独立普通管理员配置。账号规则为 `test_w星期数字_p时段数字`，例如 `test_w1_p1` 负责周一一时段，`test_w7_p5` 负责周日五时段。

本地账号和各自随机测试密码见项目根目录 `outputs/test-admins/accounts.md`，机器可读清单为同目录 `accounts.json`。选择“管理员”登录；没有赋予这些账号超级管理员权限。

账号仅由显式脚本建立，正常启动不会自动创建、重置密码或替换负责人：

```powershell
python core/scripts/setup_test_admins.py --super-account super
```

脚本在写库前保存可恢复的账号清单，整体事务创建并分配；重跑会核对清单和原密码，不重复建号。若时段后来已经改配正式负责人，脚本保留现有负责人；如同名账号与清单不符则停止，不覆盖账号或密码。

## 接口与迁移

- `POST /students/{student_id}/administrator`，请求含 `reason`、可选 `slot_ids` 数组，只允许超管；调用者不能传入管理角色来提升为超级管理员。
- `GET /admins` 仅超管可访问，返回 `student_id` 关联信息，不返回密码或哈希。
- `admin.student_id` 是可空唯一外键，引用 `student.student_id`；独立管理员为空。数据库仍为 17 张表。
- 启动器通过 `app.admin_roles.migrate` 添加关联字段，兼容已有账号和密码；新建库 SQL 同步包含该约束。
- 授权、时段负责人变化及 `PROMOTE_STUDENT` 操作日志在同一事务中提交，记录原负责人、授权原因和结果，不记录密码。

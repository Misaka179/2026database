# 图书馆志愿服务管理系统：数据库核心功能

当前实现包含 **17 张 MySQL 表、数据库约束、Python 业务服务、HTTP API 和简体中文工作台**（原 13 张业务表加时段归属、学期、学期日历、学期归属历史表）。工作台按志愿者、普通管理员和超级管理员区分功能；中文接口文档保留查询和调用入口。

最新操作说明见 [学期排班使用说明](docs/学期排班使用说明.md)。超级管理员在“学期与日历”设置开工日期和结束周次，系统生成未来服务安排并在每周结束后自动计时；内置 2026 年节假日，支持手动调休班表。

## 已实现的业务

| 功能 | 行为 |
|---|---|
| 登录与权限 | 志愿者、普通管理员、超级管理员；密码哈希；签名令牌有效期 1 小时；后端重新检查账号和角色 |
| 基础资料 | 超管手动创建或 Excel 导入队员，学院选填、学号唯一；每周 35 个固定时段，只设置负责人和人数上限 |
| 排班 | 按学期日历与固定归属自动生成；支持假期停工、调休映射、例外手动排班，检查容量和冲突 |
| 请假 | 志愿者申请本人排班，负责的普通管理员审批；获批后考勤自动认定请假，不计时、不扣分 |
| 换时段 | 仅长期调整每周固定时段，两级审批；终审原子更新归属及学期内未来排班，保留历史；单次接口返回 410 |
| 退队 | 志愿者申请，超管确认；保留历史，取消未来尚未开始的排班和相应未完成申请 |
| 考勤 | 负责人记录异常；每周一自动结算上周未登记的服务，获批请假不计时；自动正常出勤可附原因补录迟到或缺勤 |
| 时长 | 正常与迟到均计完整时长，第 3 时段 180 分钟，其余 120 分钟；按日期范围汇总有效记录；无记录返回 0 |
| 信用 | 初始 5 分，迟到扣 2、缺勤扣 3；最低 0；归零后停用并取消未来排班；名义扣分与实际变化分别记录 |
| 规则修改 | 超管发布新版本，旧版本保留；历史违规继续引用发生时的版本 |
| 时长修正 | 超管修改具体服务记录，必须填写原因，修改及日志共同提交 |
| 操作审计 | 保存操作人、对象、时间、前后值和原因；仅超管查询 |

志愿者退队或被停用后，仍可登录查看自己的历史数据，但不能再发起新的申请。审批结果相同的重试和相同考勤重试返回已处理结果；不同考勤结果不能覆盖已结算记录。

## 本机启动

本项目使用独立的本机 MySQL 实例，不更改原有 Windows MySQL 服务。

- 数据库地址：`127.0.0.1:3308`
- 应用数据库：`volunteer_core`
- 测试数据库：`volunteer_core_test`
- 当前实测引擎：MySQL **5.7.44**，来自本机 `F:/mysql5/bin`
- 数据与随机凭据：项目上一级 `.work/mysql-core/`
- 演示登录信息：项目上一级 `.work/demo-accounts.json`，其中包含随机密码，请本地查看

**推荐双击本目录的 `start.cmd`**，或在本目录打开 PowerShell 运行：

```powershell
.\start.cmd
```

也可以直接使用 Python 启动，无需运行 PowerShell 脚本：

```powershell
python .\start.py
```

如果当前位于项目上一级目录 `D:\汇报作业\数据库`，运行 `python .\core\start.py` 即可；启动器自动使用自身所在目录，不依赖终端的当前目录。

启动器依次检查独立 MySQL、初始化缺失的数据表和演示账号、启动 `127.0.0.1:8765` 网页服务，已有数据会保留。若本系统已经运行，会显示可访问的地址；若端口被其他程序占用，会提示原因并退出。服务启动后请保持窗口打开，按 `Ctrl+C` 可停止网页服务。双击启动失败时窗口会保留，便于查看错误。

若之前执行 `start.ps1` 时出现“禁止运行脚本”或 `PSSecurityException`，这是 PowerShell 执行策略阻止了脚本，网页服务尚未启动，因此浏览器可能显示“拒绝连接”。改用上面的 `start.cmd` 或 `start.py` 即可，**无需更改系统执行策略或以管理员身份运行**。只查看启动参数可运行 `python .\start.py --help`，这不会启动任何服务。

打开 [中文工作台](http://127.0.0.1:8765/)，选择登录身份，再填写账号和密码。工作台会显示该角色可使用的页面，无需手动复制令牌。也可以打开 [中文接口文档](http://127.0.0.1:8765/docs)，通过中文登录表单和调用表单验证接口。两种页面在同一标签页内共用登录状态；退出后清除该标签页保存的令牌。

页面脚本和样式由本机服务提供，页面加载不依赖 Swagger 或外部字体 CDN。页面文案、状态名称、表单提示和接口字段说明使用简体中文；接口路径、JSON 字段名与枚举值保留原有协议，便于程序调用。设计说明见 [界面说明](docs/interface.md)。

## 第一条演示流程

1. 先以 `super` 登录，在“基础资料 → 服务班次”设置一个固定时段的负责人和人数上限，再在队员列表设置学号 `20260001` 的归属时段。随后由超级管理员在“学期与日历”设置开工日期和结束周次；若该演示队员已退队，请使用仍在队的队员。
2. 退出登录，以志愿者身份使用学号 `20260001` 登录，在对应排班上点击“请假”，填写原因并提交。
3. 换回 `admin1` 登录，在“申请与审批”的“请假申请”中找到该申请，审批通过。
4. 班次结束后，在“排班与考勤”中登记考勤。已批准的请假按请假处理，不产生扣分或服务时长。
5. 志愿者可在“申请与审批”“服务时长”和“信用管理”中核对本人结果；超级管理员在时长、信用页面输入学号或姓名查询，支持部分匹配，匹配多人时按学号选择，结果显示当前志愿者姓名和学号。服务时长仍支持日期范围筛选。

操作日志详情中的“关联信息”是尚未配置中文名称的审计字段的通用显示名称，并非单独的业务类型。具体含义取决于操作：设置队员归属的 `slots` 是时段编号列表；学期同步的 `created`、`cancelled`、`issues` 分别是新增排班数、取消排班数、核对提示；自动周结算的 `settled` 是结算记录条数，`before_date` 是结算截止边界日期（不含当天），不是累计小时。“修改前／修改后”分别记录该操作前后的数据。

实际接口不会提前登记尚未结束的班次。需要立即演示全流程时，运行自动化测试；测试注入时钟在独立库中模拟不同时间点，不更改电脑时间或正式库记录。

## 数据库设计与一致性

详见 [数据字典](docs/schema.md)、[建表脚本](sql/schema.sql)、[约束触发器](sql/constraints.sql)。

相比 PPT 初稿做了几项具体调整：

- 表名统一为 snake_case；升级后共 17 张表，初始 SQL 的 13 张表需通过启动器完成迁移。
- 在 service_slot 中增加 manager_admin_id，明确普通管理员的数据范围。
- 换班申请使用 old_slot_id 表示长期换时段；旧日期换班字段仅保留用于历史查询。
- 考勤通过排班关联学生，服务记录通过考勤关联排班，去掉可推导的重复学生字段。
- 内部用整数分钟保存时长，展示时换算为小时。
- 规则采用版本记录；流水保存实际分数变化，违规保存名义扣分。
- MySQL 5.7 不执行 CHECK，因此用插入/更新前触发器实际执行取值校验。

全部业务写操作在同一库名对应的 MySQL 命名锁下串行执行，并包在 InnoDB 事务中。这样在课程项目规模下，可以可靠地检查容量、冲突和当前信用分，避免并发请求重复占位或丢失更新。它会限制写入并发量，适用于当前小规模第一版；直接绕过服务层手工执行 SQL 不受这套业务锁约束。

约束负责主外键、唯一性、非负数值等；服务层负责角色权限、人数上限、时间冲突和审批状态等跨表业务。参考：[MySQL 锁定读取](https://dev.mysql.com/doc/refman/8.0/en/innodb-locking-reads.html)、[MySQL CHECK 约束说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)。本机已验证 5.7，8.x 兼容性尚未实测。

## 第一版边界

当前已提供按角色区分的中文业务页面和中文接口调用页面。页面使用现有后端执行操作，权限、时间冲突、容量和事务规则仍由服务端检查。

已实现考勤改判、实际扣分冲正和超管调分；普通管理员可改判本时段考勤，超管可处理全队。撤销错误缺勤会恢复该次时长和实际被扣的分数，流水与审计保留历史。超管在“信用管理”选人后可调整任何队员的信用分。尚未实现独立违规申诉流程、管理员交接、密码自助找回和自动备份。规则停用当前通过新版本替换实现，没有提供让某一违规类型完全缺少有效规则的接口。

本机绑定回环地址。若后续对外部署，需要另行配置 HTTPS、登录限流、密钥管理和运维方案。


## 固定时段与 Excel 导入

周一至周日，每天五个时段，名称为“周一-一时段”至“周日-五时段”。固定时间如下：

| 时段 | 实际服务时间 | 沿用的认定时长 |
|---|---|---|
| 一 | 08:15–09:55 | 2 小时 |
| 二 | 10:15–11:55 | 2 小时 |
| 三 | 13:50–16:25 | 3 小时 |
| 四 | 16:45–18:25 | 2 小时 |
| 五 | 19:20–21:00 | 2 小时 |

没有负责人或人数上限的时段显示“待分配／待设置”，仍会按已有固定队员生成学期排班并计时，但不能手动新增排班或换入。超级管理员在“基础资料 → 服务班次”设置；没有新增班次入口。后端同时拒绝新增班次和与学期日历指定班表不匹配的服务日期。普通管理员只可查询负责时段的队员、为本时段队员排班，并处理负责时段的考勤和申请。

Excel 导入入口：“基础资料 → 志愿者 → Excel 导入”。上传 `.xlsx`，选择工作表，点击预览。前 30 行中需有“姓名”“学号”表头；“学院”可缺列或为空，分类列可名为“分类”或“时段”。确认分队数字对应星期后勾选映射选项。同一学号合并为一个账号，可以保存多个时段归属。无法匹配的分类会明确提示，仅建立账号；不会编造第 36 个时段。姓名冲突、公式学号、精度不可靠的数字学号会阻止提交。

预览无错误后设置新账号初始密码、核对提示并确认导入。已有账号的密码、信用分、姓名、学院和历史记录保持原样；已退队或停用账号不会因导入重新启用。重复导入不会重复建立账号或归属。原始工作簿不修改，也不保存到服务器；每周时长、合计、退队历史不自动变成服务记录。已配置学期时，导入会同步尚未开始的日期排班。

升级由 `app.fixed_slots.migrate` 完成，启动器自动执行。新增 `slot_member` 用复合主键 `(student_id, slot_id)` 表达多时段归属，两个字段分别是学号与班次的外键，另外增加 semester、semester_day 与 semester_member，升级后共 17 张表。旧班次只停用，保留其已有排班与历史引用。

## 自动补计与考勤纠错（2026-09-27）

首次设置学期或升级旧学期，会以当时的在队归属从开工日期补齐服务，立即结算已经结束的周次。已有缺勤、请假和手动取消保持有效；后续增员、退队及换时段保存生效日期，不追改此前时长。负责人、容量待完善只提示，不阻止既有归属计时。详细操作见 [学期排班使用说明](docs/学期排班使用说明.md)。

## 从队员授权普通管理员

超级管理员在“基础资料 → 志愿者”点击“设为普通管理员”，可选择负责时段。队员以学号和现有密码选择管理员身份登录，个人志愿服务身份与历史保留。每个固定时段已配置独立测试管理员，账号清单在项目根目录 `outputs/test-admins/accounts.md`。详见 [管理员设置使用说明](docs/管理员设置使用说明.md)。

## Windows 启动端口检查修复（2026-10-08）

若旧启动器提示“无法检查本机 8765 端口”，可能是 Windows 对关闭端口返回连接拒绝约需 2 秒，而原检测仅等待 0.5 秒。现已延长至 3 秒，超时后通过独占绑定判断端口是否空闲；仍拒绝覆盖其他程序，并保留实际访问权限错误。使用更新后的 `start.cmd` 启动即可，无需联网或关闭防火墙。
